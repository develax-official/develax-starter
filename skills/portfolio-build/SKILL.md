# portfolio-build: 공개용 site/ 만들기

대상 사용자는 비개발자입니다. 코드는 사용자에게 보여주지 않고, 결과를 브라우저로 보여주고 말로 고칩니다.
`portfolio` 스킬의 **공통 원칙**을 그대로 따릅니다. 특히 **기록에 없는 문장은 넣지 않습니다.**
템플릿은 이 스킬 폴더의 `templates/` 에 있습니다: `index.html`, `style.css`, `print.css`, `robots.txt`, `_headers`.

## 0. 재료 확인

1. 현재 폴더에 `PORTFOLIO.md` 가 없으면 `/portfolio` 로 안내합니다.
2. `작업/2-경험카드.md` 와 `작업/3-JD매칭.md` 가 있는지 봅니다. 없으면 "경험 카드와 JD 매칭을 먼저 하면 직무에 맞는 포트폴리오가 됩니다. 먼저 할까요?" 묻고, 동의하면 `portfolio` 스킬 3~5번을 합니다. 사용자가 그냥 만들자고 하면 있는 기록으로 만들되 `작업/` 이 비어 있다는 사실을 끝에 다시 알립니다.
3. `나.md` 에서 이름, 지원 직무, 이메일, 링크를 읽습니다. 비어 있으면 그 칸만 묻습니다.

## 1. 폴더 만들기

`site/` 가 없으면 만듭니다. 있으면 덮어쓰기 전에 `site/index.html` 을 `작업/이전버전/index-<YYYYMMDD-HHMM>.html` 로 복사해 둡니다.

```
site/
├── index.html
├── robots.txt
├── _headers
└── assets/
    ├── css/style.css
    ├── css/print.css
    ├── images/
    └── files/
```

- `templates/style.css` → `site/assets/css/style.css`, `templates/print.css` → `site/assets/css/print.css`, `templates/robots.txt`, `templates/_headers` 는 그대로 복사합니다.
- `site/` 밖의 파일을 `site/` 안에서 참조하지 않습니다(배포하면 깨집니다).

## 2. 이미지와 파일

1. 대표 프로젝트의 `캡처/` 에서 프로젝트당 1~2장을 고릅니다. 무엇을 보여주는 이미지인지 모르면 묻습니다.
2. `site/assets/images/` 로 복사하면서 이름을 **영문 소문자와 `-`** 로 바꿉니다. 예: `캡처/출석화면 최종.png` → `attendance-main.png`. 한글·공백 파일명은 주소가 깨질 수 있습니다.
3. 가로 1600px 또는 1MB 를 넘으면 줄입니다. Mac: `sips -Z 1600 <파일>`. 줄일 도구가 없으면 그대로 두고 "이미지가 커서 느릴 수 있습니다"라고 알립니다.
4. 이미지 속에 회사 기밀이나 개인정보(실명, 연락처, 내부 주소)가 보이면 넣기 전에 알립니다. Claude가 이미지를 가릴 수는 없으니 사용자에게 가린 캡처를 달라고 합니다.
5. `나.md` 에 이력서 PDF 가 있으면 `site/assets/files/` 로 복사하고 연락처 섹션에 내려받기 링크를 답니다. 파일명은 영문(`resume.pdf`).

## 3. index.html 만들기

`templates/index.html` 의 구조를 채웁니다. 구성은 강의에서 확정한 네 칸입니다.

| 섹션 | 내용 | 재료 |
|---|---|---|
| 소개 | **누구를 위해 무엇을 하는 사람인지** 한 문장 + 지원 직무 + 핵심 역량 태그 3개(JD 단어 그대로) | 나.md, 3-JD매칭.md |
| 대표 프로젝트 | JD 매칭의 "강조할 것" 2~3개, **JD 요구 역량 순서**로. 프로젝트마다 기간·역할·팀·도구, 그리고 **문제 → 판단 → 행동 → 결과** 네 칸, 이미지 1~2장, 연결되는 JD 역량 태그 | 2-경험카드.md, 캡처 |
| 주요 경험 | 나머지 경험은 한 줄씩 짧게 (기간, 소속, 한 일) | 1-경험정리.md, 나.md |
| 연락처 | 이메일, 링크, 이력서 PDF | 나.md |

작성 규칙:
1. 문장은 경험 카드에서 가져옵니다. 다듬어도 되지만 **뜻을 바꾸거나 숫자·역할을 키우지 않습니다.** "리드", "주도", "총괄" 은 기록에 그렇게 있을 때만.
2. 아직 `확인 필요` 인 칸은 `<mark class="todo">확인 필요: 결과 수치</mark>` 처럼 노란 칸으로 남깁니다. 그럴듯한 문장으로 메우지 않습니다.
3. 판단 칸이 가장 눈에 띄게 합니다(템플릿의 `.card-why` 강조 스타일).
4. 경로는 모두 상대 경로(`assets/images/...`). `/` 로 시작하는 절대 경로는 GitHub Pages 에서 깨집니다.
5. 외부 라이브러리, 빌드 도구, JavaScript 프레임워크를 쓰지 않습니다. 파일을 더블클릭해도 열려야 합니다.
6. `<head>` 의 제목, 설명(`description`, `og:title`, `og:description`)을 채웁니다. 메신저로 링크를 보낼 때 미리보기에 쓰입니다.
7. 이미지에는 무엇을 보여주는지 `alt` 를 씁니다.
8. 디자인은 지원 직무에 맞게 차분하게. 포인트 색 한 가지(`style.css` 의 `--accent`)만 바꿉니다. 사용자가 색을 말하지 않으면 템플릿 기본값을 씁니다.

## 4. 검색 노출 막기

포트폴리오는 지원하는 회사에 링크로 보내는 용도라서 검색 엔진에 나오지 않게 합니다. 세 겹으로 막습니다.

1. `site/robots.txt`: 모든 검색 로봇과 AI 수집 로봇에게 **어디도 수집하지 말라**고 요청합니다(`Disallow: /`). 템플릿 그대로.
2. `index.html` 의 `<meta name="robots" content="noindex, nofollow, noarchive">`: 페이지를 검색 결과에 넣지 말라는 표시. 템플릿에 들어 있으니 지우지 않습니다.
3. `site/_headers`: Cloudflare 로 배포할 때 모든 파일에 `X-Robots-Tag: noindex` 를 붙입니다. GitHub Pages 에서는 무시되며 해가 없습니다.

사용자에게 설명할 때는 이렇게 말합니다:
> 검색에 안 나오도록 설정했습니다. 다만 **비공개는 아닙니다.** 주소를 아는 사람은 누구나 열 수 있으니, 전화번호·집 주소는 넣지 않았습니다. robots.txt 는 "수집하지 말아 달라"는 요청이라 규칙을 지키지 않는 로봇까지 막지는 못합니다.

사용자가 "검색에 나오게 해줘" 라고 하면 robots.txt 를 `Allow: /` 로 바꾸고 meta robots 와 `_headers` 를 지웁니다. 이때 위 경고를 한 번 더 합니다.

## 5. 인쇄용 CSS

`site/assets/css/print.css` (`<link media="print">`)가 브라우저의 인쇄·PDF 저장을 처리합니다. 템플릿이 하는 일:
- A4, 여백 15mm, 흰 배경 검은 글자 (배경색 때문에 잉크·가독성 문제가 생기지 않게)
- 상단 메뉴, 버튼, 장식 요소는 숨김
- 링크 뒤에 실제 주소를 괄호로 출력 (종이에서도 주소를 알 수 있게)
- 프로젝트 카드와 이미지가 페이지 중간에서 잘리지 않게, 대표 프로젝트는 새 페이지에서 시작
- `확인 필요` 노란 칸은 인쇄에도 보임 (고치지 않고 제출하는 일을 막기 위해)

만든 뒤 안내:
> PDF 로 저장하려면 브라우저에서 Cmd+P (Windows: Ctrl+P) → 대상 "PDF로 저장" → 저장. 여백은 "기본값", 머리글·바닥글은 끄면 깔끔합니다.

## 6. 보여주고 고치기

1. 브라우저로 엽니다: Mac `open site/index.html`, Windows `start site\index.html`. Code 탭의 브라우저 패널을 쓸 수 있으면 거기서 엽니다.
2. "창 너비를 줄여서 휴대폰 화면도 확인해 보세요"라고 말합니다.
3. 사용자가 "좋아요"라고 할 때까지 한 번에 하나씩 고칩니다. 자주 나오는 요청: 첫 문장 바꾸기, 프로젝트 순서, 포인트 색, 여백, 이미지 교체.
4. 수정 요청에 기록에 없는 사실이 들어 있으면(예: "성과를 30% 올렸다고 써줘") 근거를 묻고, 근거가 없으면 "면접에서 질문받으면 설명할 수 있는 숫자인가요?"라고 확인합니다. 사용자가 원하면 넣되 `개요.md` 에 "(사용자 답변)" 으로 출처를 남깁니다.

## 7. 끝맺음

`PORTFOLIO.md` 진행 표의 6단계를 완료로 바꾸고 출력합니다:
> `site/` 를 만들었습니다. 대표 프로젝트 n개, 이미지 n장, 확인 필요 n칸.
> 검색 노출 막기와 인쇄용 설정이 들어 있습니다.
