# portfolio: 내 기록으로 웹 포트폴리오 만들기

대상 사용자는 비개발자 구직자입니다. 한국어로, 짧게, 한 번에 질문 하나. 한 단계가 끝나면 결과를 보여주고 "다음 단계로 갈까요?" 묻습니다.
이 스킬은 DEVELAX 강의 "AI로 포트폴리오 만들기"의 흐름을 그대로 따릅니다. 핵심 문장: **내가 만족하는 포트폴리오와 상대방(채용 담당자)이 만족하는 포트폴리오는 다를 수 있다.**

## 공통 원칙 (모든 단계)

1. **기록에 없는 내용은 지어내지 않습니다.** 역할, 숫자, 결과, 이름이 기록에 없으면 `확인 필요` 로 남기고 사용자에게 묻습니다. 폴더 밖에서 알게 된 정보(이전 대화, 일반 지식)로 경력을 채우지 않습니다.
2. **회사 기밀·개인정보를 지킵니다.** 고객사 실명, 내부 매출, 사내 URL, 동료 실명, 주민번호, 집 주소, 전화번호를 발견하면 알리고 가리거나 빼자고 제안합니다.
3. **공개되는 것은 `site/` 폴더뿐입니다.** 원본 기록(프로젝트 폴더, 채용공고.md, 작업/)은 내 컴퓨터와 비공개 저장소에만 둡니다.
4. 기존 파일은 덮어쓰지 않습니다. 바꿔야 하면 먼저 묻습니다.
5. 단계가 끝날 때마다 `PORTFOLIO.md` 의 진행 표를 갱신합니다.

## 0. 시작 위치 정하기

1. 현재 폴더에 `PORTFOLIO.md` 가 있으면 이어서 하는 중입니다. 진행 표를 읽고 "지난번에 <단계>까지 했습니다. <다음 단계>부터 할까요?" 묻습니다.
2. 없으면 현재 폴더를 봅니다.
   - 비어 있으면 → 여기에 만듭니다.
   - `프로젝트`로 시작하는 폴더나 `채용공고.md` 가 이미 있으면(강의 실습 폴더) → 이 폴더를 그대로 쓰고 **없는 것만** 추가합니다.
   - 다른 파일이 섞여 있으면 → "포트폴리오 전용 폴더를 새로 만들까요? 이름은 `내포트폴리오` 로 할까요?" 묻고 만든 뒤 그 폴더에서 진행합니다.

## 1. 폴더 만들기

아래 구조를 만듭니다. 템플릿은 이 스킬 폴더의 `templates/` 에 있습니다(`PORTFOLIO.md`, `나.md`, `채용공고.md`, `프로젝트-개요.md`). 이미 있는 파일은 건드리지 않습니다.

```
내포트폴리오/
├── PORTFOLIO.md          진행 상황. 이 파일이 있으면 포트폴리오 작업 폴더로 인식
├── 나.md                 기본 정보: 이름, 지원 직무, 한 줄 소개, 연락처, 링크, 경력·학력 요약
├── 채용공고.md           지원할 공고 원문 (회사가 바뀌면 이것만 교체)
├── 프로젝트1-<이름>/     프로젝트마다 폴더 하나 (2~3개면 충분)
│   ├── 개요.md           기간, 상황, 내 역할, 한 일, 도구, 결과
│   ├── 회의메모.md       결정과 그 이유 (판단 칸의 재료)
│   ├── 회고.md           잘한 점, 아쉬운 점
│   ├── 자료/             원본 문서 복사본 (형식 자유)
│   └── 캡처/             화면, 산출물 이미지
├── 작업/                 AI 정리 결과가 단계별로 쌓이는 곳
│   ├── 1-경험정리.md
│   ├── 2-경험카드.md
│   ├── 3-JD매칭.md
│   ├── 4-검증표.md
│   └── 5-루브릭.md
└── site/                 인터넷에 공개되는 폴더 (이것만 배포)
    ├── index.html
    ├── robots.txt        검색 노출 막기
    ├── _headers          검색 노출 막기 (Cloudflare용)
    └── assets/
        ├── css/          style.css, print.css
        ├── images/       캡처에서 고른 이미지 (영문 파일명)
        └── files/        이력서 PDF 등 내려받을 파일
```

- 프로젝트 폴더는 처음에 `프로젝트1-이름바꾸기/` 하나만 템플릿으로 만들고, 실제 프로젝트는 2번에서 채웁니다.
- 폴더를 만든 뒤 구조를 짧게 보여주고 "정리 안 된 기록도 괜찮습니다. 메모, 문서, 캡처 무엇이든 넣으면 됩니다"라고 말합니다.

## 2. 재료 채우기

세 가지를 차례로 채웁니다. 한 번에 하나씩 묻습니다.

1. **채용공고.md**: "지원하고 싶은 공고를 붙여 주세요. 공고 주소만 주셔도 됩니다." 주소를 주면 페이지를 읽어 담당업무·자격요건·우대사항을 원문 그대로 옮깁니다(요약하거나 바꾸지 않음). 공고가 없으면 관심 직무 공고 하나를 골라 달라고 합니다.
2. **나.md**: 이름(또는 공개용 이름), 지원 직무, 연락처는 **이메일만** 권합니다. 전화번호·집 주소는 공개 사이트에 넣지 않습니다.
3. **프로젝트**: `portfolio-project` 스킬로 프로젝트 2~3개의 자료를 모읍니다. 사용자가 이미 폴더에 넣어 두었으면 건너뜁니다.

## 3. 경험 정리 (강의 실습 2)

모든 프로젝트 폴더의 기록을 읽고 프로젝트별 표를 만들어 `작업/1-경험정리.md` 에 저장합니다.

- 열: 프로젝트 / 기간 / 내 역할 / 내가 한 일 / 사용한 도구 / 결과 / 근거 파일
- 기록에 없는 칸은 `확인 필요`. 근거 파일 열에는 그 내용이 나온 파일 이름을 적습니다.
- 끝나면 `확인 필요` 칸 개수를 알려주고, 가장 중요한 것(보통 내 역할, 결과 수치)부터 3개까지 질문합니다. 답은 해당 프로젝트의 `개요.md` 에 "(사용자 답변, 날짜)" 표시와 함께 적어 원본 기록으로 남깁니다.

## 4. 경험 카드 (강의 실습 3)

프로젝트마다 **문제 → 판단 → 행동 → 결과** 네 칸 카드를 만들어 `작업/2-경험카드.md` 에 저장합니다.

- 문제: 무엇이 잘못돼 있었나 / 판단: 왜 그렇게 결정했나 / 행동: 실제로 무엇을 했나 / 결과: 무엇이 달라졌나
- **판단 칸이 핵심**입니다. 회의메모·회고에서 결정 이유를 찾아 쓰고, 없으면 지어내지 말고 질문합니다. 예: "운영자가 기준 시간을 바꿀 수 있게 한 이유가 기록에 '과정마다 수업 방식이 다름'으로 있습니다. 이 판단을 누가 제안했나요?"
- 각 칸 끝에 근거 파일을 괄호로 적습니다.

## 5. JD 매칭 (강의 실습 4)

`채용공고.md` 에서 요구 역량 5개를 뽑고(자격요건·우대사항·담당업무의 단어를 그대로), 각 역량에 경험 카드를 연결해 `작업/3-JD매칭.md` 에 저장합니다.

- 표: 요구 역량 / 공고 원문 / 연결되는 내 경험 / 근거
- 포트폴리오에서 **강조할 것 3개**와 **뺄 것 3개**를 고릅니다. 뺄 것에 아까운 게 있어도 빼자고 권합니다(직무와 연결 안 되는 경험은 읽는 사람의 시간을 씁니다).
- 연결되는 경험이 없는 역량은 숨기지 말고 "이 역량은 경험이 비어 있습니다. 관련 기록이 있으면 추가해 주세요"라고 알립니다.
- 마지막에 목차를 확정합니다: 소개 / 대표 프로젝트(강조할 것, JD 역량 순) / 주요 경험 / 연락처. 사용자 확인을 받습니다.

## 6. 제작

`portfolio-build` 스킬로 `site/index.html` 을 만듭니다. 검색 노출 막기(robots.txt), 인쇄용 CSS, 이미지 정리가 포함됩니다. 브라우저로 열어 보여주고 "좋아요"가 나올 때까지 한 번에 하나씩 고칩니다.

## 7. 검증과 점수

`portfolio-review` 스킬로 모든 문장을 원본 기록과 대조하고(`작업/4-검증표.md`), 루브릭 점수표(`작업/5-루브릭.md`)를 만듭니다. 사실성 항목이 기준 미달이면 공개 전에 고치자고 합니다.

## 8. 공개

1. 공개 전 마지막 확인: `site/` 안에 전화번호·집 주소·회사 기밀이 없는지, `확인 필요` 가 남아 있지 않은지.
2. "인터넷에 공개할까요? `/deploy-pages`(GitHub Pages, 전자동) 또는 `/deploy-cloudflare`(Cloudflare) 중 고르세요. 어느 쪽이든 `site/` 폴더만 올라갑니다" 라고 안내합니다. 원본 기록 보관은 `/save`(비공개)입니다.
3. robots.txt 로 검색 노출을 막아 두었으므로 "주소를 아는 사람만 볼 수 있고, 구글 검색에는 나오지 않도록 요청해 둔 상태입니다"라고 덧붙입니다.

## 9. 이후 관리

"포트폴리오 업데이트", "새 프로젝트 넣어줘", "다른 회사에 지원해" 요청:
- 새 프로젝트: `portfolio-project` → 3~5단계 해당 부분만 다시 → `portfolio-build` 로 반영 → `portfolio-review`.
- 지원 회사가 바뀜: `채용공고.md` 만 교체(이전 공고는 `작업/` 에 날짜 붙여 보관) → 5단계부터 다시.
- 끝나면 "수정한 걸 올리려면 `/deploy-pages`(또는 DEPLOY.md에 적힌 방식)" 라고 안내합니다.
