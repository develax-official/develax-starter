# launch: 홈페이지, 만들기부터 공개까지 한 번에

대상 사용자는 비개발자입니다. 한국어로, 짧게, 한 번에 한 질문만. 이 스킬은 아래 부품 스킬을 **순서대로 이어서** 실행합니다. 각 부품의 규칙(비밀번호·sudo 금지, reset --hard 금지, 토큰 저장 금지)을 그대로 따릅니다.

```
0. 사전 점검   (setup-check)
1. 무엇을 만들지 묻기
2. index.html 만들기 + 미리보기 + 고치기
3. GitHub에 보관   (save, 공개 저장소)
4. GitHub Pages 배포   (deploy-pages)
5. 주소 전달 + 다음에 고치는 법
```

## 0. 사전 점검

`setup-check` 의 1번(점검 실행)을 수행합니다. ❌가 있으면 멈추고 setup-check 의 대응 절차로 안내합니다. 여기서 억지로 진행하지 않습니다.

현재 폴더에 이미 `index.html` 이 있으면 "이미 만들어 둔 페이지가 있네요. 이걸 그대로 올릴까요, 새로 만들까요?" 를 묻고, 그대로 올리면 **3번**으로 건너뜁니다.

폴더가 비어 있지 않고 index.html 도 없으면(다른 파일이 섞여 있으면) "이 폴더에 홈페이지를 만들면 안의 파일이 함께 공개됩니다. 새 폴더에서 할까요?" 를 묻습니다.

## 1. 무엇을 만들지 묻기: 질문 3개만

한 번에 하나씩 묻습니다. 답이 짧아도 됩니다.
1. "무슨 홈페이지예요? (예: 내 소개 / 우리 동호회 / 가게 안내 / 포트폴리오)"
2. "맨 위에 크게 들어갈 제목과 한 줄 소개는요? (예: 홍길동, 서비스 기획자)"
3. "본문에 넣을 내용 3가지만 알려주세요. (예: 하는 일 / 해온 것 / 연락처)". 연락처를 넣겠다면 "전화번호·집 주소는 인터넷에 공개됩니다. 이메일이나 SNS만 넣는 걸 권해요"라고 한 번 말합니다.

디자인은 묻지 않습니다. 기본값으로 만들고 2번에서 고칩니다.

## 2. index.html 만들기

규칙:
- 파일은 `index.html` **하나**. CSS·JS 는 그 안에. 외부 라이브러리·빌드 도구·프레임워크 없음.
- 모든 링크·이미지 경로는 **상대 경로**(`img/photo.jpg`). `/` 로 시작하는 경로 금지 (GitHub Pages 주소가 하위 경로이기 때문).
- 모바일에서 깨지지 않게. 포인트 색 하나. 깔끔하고 단순하게.
- 구성: 상단(제목, 한 줄 소개) → 1번에서 받은 내용 3가지를 카드나 섹션으로 → 하단(연락처 또는 한 줄 인사).
- `<title>` 은 제목으로, `<meta name="viewport">` 포함.

만든 뒤:
1. 브라우저 패널로 열어 보여줍니다.
2. "마음에 드세요? 고치고 싶은 곳을 말해 주세요. (색, 글자 크기, 내용, 순서… 뭐든) 괜찮으면 '좋아요'라고 해 주세요."
3. 사용자가 고쳐 달라는 대로 고치고 다시 보여줍니다. **'좋아요'가 나올 때까지** 반복합니다. 재촉하지 않습니다.
4. 사진을 넣고 싶다고 하면: 폴더 안에 `img/` 를 만들고 "사진 파일을 img 폴더에 넣고 알려주세요"라고 안내한 뒤, 넣었다고 하면 상대 경로로 넣습니다. 파일명이 한글·공백이면 영문으로 바꿔 줍니다.

## 3. GitHub에 보관

`save` 스킬의 1번(처음 저장)을 수행하되, 이 경우는 **공개(public) 저장소**로 만듭니다. GitHub Pages 조건이기 때문입니다.
- 저장소 이름 확인 질문: "GitHub 저장소 이름은 `<폴더명>` 으로 할까요? (주소에 들어갑니다: https://<아이디>.github.io/<이름>/)"
- 공개 안내 한 줄: "이 저장소는 공개입니다. 폴더 안 파일 전부가 누구나 볼 수 있어요."
- `.gitignore`, `.nojekyll` 생성 포함.

## 4. GitHub Pages 배포

`deploy-pages` 스킬의 3번(Pages 켜기)과 4번(주소 확인)을 수행합니다. 저장소는 3번에서 이미 만들었으므로 `gh repo create` 는 다시 하지 않습니다.
- 주소를 먼저 보여주고 "첫 배포는 1~3분 걸려요"라고 말한 뒤, built 가 될 때까지 30초 간격으로 최대 6번 확인합니다.
- `DEPLOY.md` 를 만들어 저장소 주소·사이트 주소·배포 방식을 적고 commit·push 합니다. HTTPS 강제는 하지 않습니다(deploy-pages 3번과 같음).

## 5. 마무리

아래 형식으로 끝맺습니다.

> **공개됐습니다.** https://<아이디>.github.io/<이름>/
> 휴대폰으로도 한 번 열어 보세요.
>
> 앞으로 고칠 때는 이렇게 말하면 됩니다.
> - 내용 바꾸기: "두 번째 카드 내용을 ○○로 바꿔줘" → 고친 뒤 `/deploy-pages` (1~2분 뒤 사이트에 반영)
> - 되돌리기: "방금 바꾼 거 되돌려줘"
> - 주소는 그대로, 내용만 새로워집니다.

## 중간에 막히면

| 상황 | 대응 |
|---|---|
| 0번에서 ❌ | 멈추고 setup-check 안내. "준비가 끝나면 다시 /launch 하세요" |
| 사용자가 2번에서 "나중에 고칠게" | 그대로 3번 진행. 언제든 고칠 수 있다고 안내 |
| 저장소 이름 중복 | `-2` 붙여 다시 확인 |
| Pages 가 3분 넘게 안 됨 | 주소를 주고 "조금 뒤 열어 보세요. 안 되면 저장소 Settings → Pages 캡처를 보여주세요" |
| Cloudflare 로 올리고 싶다고 함 | `/deploy-cloudflare` 로 안내 (Cloudflare 는 대시보드 클릭이 한 번 필요하다고 설명) |
